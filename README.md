# dsh-style-guard

模型把话说出来之前先看一遍。难读的地方就地改掉，页面上出现的是改完的版本，
难读的原稿不会先显示一次。

## 它解决什么

同一个模型，让它专心解技术问题，写出来的回复经常难读。把那段回复单独交给它，
只让它挑毛病，它又能挑得很准。这个插件就是把后面这一步固定下来，装进每次回复的路上。

## 怎么工作

1. 认出这是主对话在写回复，并且够长、这一轮没有调用工具。
2. 把模型吐出来的字先收着，一个字都不往外放。
3. 单独发一次模型调用，给它你这一轮问的话、这段回复、你的回复规范和插件自带的编辑手册，让它挑毛病。先看整段像不像一个人在说话，再看具体用词。
4. 再发一次，让它把这段话重新讲一遍，可以调顺序、并段落、把程序内部的说法换成你看得到的结果。最多两轮，第二轮只在第一轮改完还有明显问题时才做。
5. 核对改写前后的数字，少一个就整段作废，用原文。
6. 把结果交给上层。页面显示的和写进会话记录的是同一份。

插件自己任何一步出错或超时，都放行原文。

## 安装

```sh
dsh plugin --profile web add github:chen-001/dsh-style-guard
```

`lib/` 已随仓库提交，git 安装不需要授权运行构建脚本。

本地开发时这个包也可以直接注入：`bash scripts/build.sh` 之后用注入器挂上。

## 配置

配置有两处，后一处覆盖前一处。

1. profile 的 patch 里那一行 `config`。
2. `~/.dsh/style-guard/config.json`。改这里不用重新构建，重载插件即可生效。

| 字段 | 默认 | 含义 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉就完全不工作。 |
| `dryRun` | `true` | 只检查、只记日志，页面显示原文。确认改得好再关掉。 |
| `minChars` | `500` | 正文短于这个字数就不检查。 |
| `rounds` | `1` | 检查加改写做几轮，代码上限 2。 |
| `maxExtraMs` | `90000` | 检查和改写合计最多花多少毫秒，超了用手上已有的版本。 |
| `onlyRootAgents` | `true` | 只处理主对话，跳过子 agent 的调用。 |
| `sessions` | `[]` | 只处理这些会话，留空表示全部。 |
| `provider` / `model` | `''` | 检查和改写用哪个模型，留空表示跟主模型一致。 |
| `rewriteEffort` | `''` | 改写那一步的思考档位，留空不思考。不思考时改写器基本只换词，填 `low` 才会重新组织句子，每条回复多等十几到三十秒。 |
| `verbose` | `false` | 把每次跳过的原因也写进日志。 |
| `trace` | `false` | 把每一次模型调用都写进日志，排查"插件有没有收到事件"时用。 |
| `auditPath` | `~/.dsh/style-guard/log.jsonl` | 审查记录。每次检查一行，原文和改写版全文都在里面。 |
| `rubricPath` | `~/.dsh/AGENTS.md` | 规范文件。插件每次都现读里面"回复风格"那几节。 |

## 规范从哪来

插件读 `rubricPath` 指向的文件里所有以"回复风格"开头的二级小节，每次调用前现读。
所以你改规范，检查标准自动跟着变，不存在两份规则不一致的问题。

## 日志

`~/.dsh/style-guard/log.jsonl`，一行一条，字段包括

- `kind`，`review` 是一次检查，`skip` 是跳过的原因，`error` 是出错。
- `original` 和 `rewritten`，原文和改写后的全文。
- `problems`，检查给出的问题清单。
- `ms`、`roundsRun`、`rejected`，耗时、实际改了几轮、因事实对不上被作废的痕迹。

原文只留在这里，不进对话。日志会随时间变大，隔一段时间清一次。

## 已知边界

- 改写由另一次模型调用完成，它只看到这段回复，看不到代码，所以它只能改措辞。
  数字、路径、反引号里的名字有机械核对兜底，但表述上的细微差别它判断不了。
- 回复是收完再显示的，所以长回复会晚二十秒左右出现，取决于轮数。
- 它站在每次回复的必经之路上，任何异常都退回原文，不会卡住对话。
